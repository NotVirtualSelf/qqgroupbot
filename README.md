# QQ Bot (C++ with Boost.Asio & Boost.Beast & Glaze)

基于 C++23、Clang、Conan 2、Boost.Asio + Boost.Beast、**Glaze** 与 **SQLite3 + libcurl** 的现代化 QQ 音乐机器人工程。  
协议端使用 **NapCatQQ**（OneBot 11 协议标准），通过 Docker 容器化运行。

---

## 🌟 核心特性

- **多平台音乐支持**：完整支持**网易云音乐**与 **QQ 音乐**两大多源音乐平台。
- **候选防错与消歧**：关注/取关均提供合并转发卡片，展示艺术家封面、代表热曲与 ID，支持多选、一键全部与取消操作。
- **新歌/新专辑智能监控与手动查询**：
  - **定时轮询与手动查询**：默认每 20 分钟轮询，同时支持群内手动发送 `/查新歌` 实时检查；
  - **单曲与专辑智能识别**：单曲发布识别为新单曲，多曲目识别为新专辑，卡片排版自动适配；
  - **严格顺序逐个推送**：每个新歌的“前置通知 $\to$ 合并转发详情卡片 $\to$ 平台音乐分享卡片”三者完整发送完毕后再推送下一个，杜绝不同作品消息混杂；
  - **跨平台 24 小时排重**：同一作品在不同平台发布时，一天内仅推送首个轮询到的平台；
  - **首次关注预热防刷屏**：关注新艺术家时自动预热历史专辑记录，避免老艺术家刷屏。
- **每日音乐推荐与 QQ 表情互动闭环**：
  - 默认每天 **09:00** 自动推送日推歌曲，**23:40** 自动执行静默反馈结算（时间支持通过指令动态更改与持久化）；
  - **平台配置抽象（严禁硬编码）**：网易云日推容量上限（35 首）、每日推荐更新分界线（06:00）、默认推送时间（09:00）、默认结算时间（23:40）统一抽象至 `NeteasePlatformConfig`；
  - **日推周期分界与跨日映射**：以平台更新基准分界线（06:00）划分周期，06:00~24:00 归属“今日”，00:00~06:00 归属“次日”，天然支持跨午夜时间设置与调度；
  - **群日推管理员权限控制**：日推的开启、关闭、重置、结算、时间设置仅限管理员操作（普通成员触发拦截提示 `✕ | 权限不足，需管理员操作`）；普通的 `/日推`、`/日推 状态` 与 `/日推 当前设置` 所有人均可发起；
  - **账号日推槽位映射与线性探测机制**：同一音乐账号（以 UID 区分）为不同群分享不同歌曲，依绑定先后顺序固定映射到日推中的第 1 首（slot 0）、第 2 首（slot 1）...；群解绑释放槽位，后续新群绑定时优先采用线性探测法探测空位置填补（如 slot 2 释放后，新群被分配 slot 2 即第 3 首歌）；
  - **单账号绑定上限与超限回滚保护**：单账号绑定群数上限为 35 个；达到上限时拦截登录导入与共享操作，提示 `✕ | 共享该账号的群聊数量达到上限。`，并自动回滚清除相关信息；
  - **群独立评价与单群结算**：各群表情回应与投票数据（👍/👎）完全独立，仅展示本群数据；结算单群独立进行，互不冲突；
  - **提前手动触发与防重**：若在默认推送前群内已手动触发 `/日推`，自动跳过当日默认推送，并将首次手动发送作为日推主体；
  - **重复触发引用回复**：群内再次触发 `/日推` 时，自动对首条日推音乐卡片进行引用回复，提示当前歌曲；
  - **表情回应互动投票**：实时捕获群内表情互动（**「对的对的」** 点赞、**「不对不对」** 踩），投票数据严格绑定在首条音乐卡片；
  - **静默反馈结算**：赞数 > 踩数 + 3 自动网易云点赞，踩数 $\ge$ 赞数自动减少推荐；支持群内手动提前结算 `/日推 结算`；
  - **状态重置与防跨时保护**：支持 `/日推 重置`，清空当日记录与评价，且过了推送时间不会自动补发默认推送；若当前已过默认结算时间则自动拦截不可重置；
  - 基于 `IDailyRecommender` 的低耦合开放式推荐接口，便于未来扩展其他平台或专辑推荐。
- **艺术家头像每日静默更新**：每日定时无感刷新已关注艺术家的头像缓存，确保卡片视觉信息最新。
- **管理员机制与多群账号管理**：
  - **QQ 号白名单模式**，支持代码级硬性管理员保护（不可被指令移除）；
  - 群聊严格拦截敏感操作，仅允许管理员私聊登录与管理；
  - 纯本地 `qrencode` 生成 Base64 二维码与专属直链，异步轮询扫码状态并持久化登录凭据至指定 QQ 群；
  - 支持直接导入 Cookie 凭据绕过官方 8821 风控，支持 VIP 会员状态实时查询展示；
  - 支持跨群账号共享（`/共享账号`）与覆盖安全确认机制。

## 🛠️ 项目环境

- **编译器**：Clang 23+ (`clang` / `clang++`)
- **C++ 标准**：C++23 (`202302L`)
- **包管理器**：Conan 2.x
- **核心依赖**：
  - `boost/1.86.0`（Asio 异步网络通信、Beast HTTP/WebSocket、UUID）
  - `openssl/3.3.2`（HTTPS / WSS 安全连接）
  - `glaze/8.4.0`（极致性能的现代 C++ JSON 序列化/反序列化库）
  - `sqlite3/3.47.2`（轻量级本地关系型数据库，存储艺术家订阅、推送记录与配置）
  - `libcurl`（高性能 HTTP 客户端，调用音乐平台 API）
  - `qrencode`（本地系统二维码生成工具）
- **构建系统**：CMake 3.20+ 与 CMakePresets
- **协议端**：NapCatQQ (`mlikiowa/napcat-docker`)

## 💡 核心业务机制详解

### 1. 关注与取关的防错消歧机制
- **候选防错卡片**：搜索出的前 5 位艺术家信息合并为转发卡片，排布规范为“名字 (ID) $\to$ 头像封面 $\to$ 代表热曲”，直观易辨。
- **结构化确认响应**：
  - 关注成功与跳过展示清晰边框：
    ```text
    ┏⊕ Added━
    ┃[网易云] Porter Robinson
    ┣⊗ Skipped━
    ┃[网易云] Virtual Self
    ```
  - 取关展示：
    ```text
    ┏⊖ Removed━
    ┃[网易云] Porter Robinson
    ```
- **视觉宽度保护**：超长艺术家名称依据保守的视觉预算进行字符截断（省略部分替换为 `...`），确保移动端界面整洁。

---

### 2. 新歌/新专辑智能监控与严格顺序推送
- **轮询周期与手动检查**：默认每 **20 分钟** 轮询所有已关注艺术家的最新作品，亦可在群内发送 `/查新歌` 随时手动触发。
- **单曲与专辑智能识别**：
  - **新单曲**（曲目数 $= 1$）：
    - 前置提示：`关注的艺术家【艺术家名】在【音乐平台】发布了新单曲！`；
    - 合并转发卡片字段：封面、单曲（`「曲名」`）、创作者（`「创作者」`）、基本信息（`「时长」`）。
  - **新专辑**（曲目数 $\ge 2$）：
    - 前置提示：`关注的艺术家【艺术家名】在【音乐平台】发布了新专辑！`；
    - 合并转发卡片字段：封面、专辑（`「专辑名」`）、创作者（`「创作者」`）、基本信息（`「x首 · xx分xx秒」`）以及完整曲目列表。
- **严格顺序逐个推送（杜绝交叉混杂）**：
  - 每个新歌消息严格按照三步流水线发送：
    $$\text{前置通知文本} \xrightarrow{\text{发送确认}} \text{合并转发详情卡片} \xrightarrow{\text{发送确认}} \text{平台音乐分享卡片}$$
  - 一个作品的全部消息完整送达后，方开始推送下一个作品；配备超时兜底机制防队列死锁。
- **跨平台 24 小时排重**：当艺术家在不同平台同时发布同名作品时，24 小时内仅推送首个检测到的平台，后续平台静默入库标记。
- **首次关注预热防刷屏**：关注艺术家成功后，自动将其历史作品标记为已推送，避免新关注时历史作品刷屏。

---

### 3. 每日音乐推荐与 QQ 表情互动闭环
- **默认推送与结算时间（可自定义配置）**：
  - 默认每天 **09:00** 自动拉取网易云日推第 1 首歌曲发送至已启用的群聊，**23:40** 执行静默评价结算；
  - 支持通过 `/日推 推送时间 <HH:MM>` 与 `/日推 结算时间 <HH:MM>` 随时更改时间并即时重置后台定时器；
  - 时间校验规则：默认结算时间不可早于默认推送时间（否则拦截提示 `✕ | 默认结算时间不可早于默认推送时间`）。
- **06:00 周期更新分界线与跨日映射**：
  - 以每日 **06:00** 为周期分界线，06:00~24:00 归属“今日”，00:00~06:00 归属“次日”；
  - 时间配置自动识别（如结算时间设为 `01:30` 回复 `➥ | 日推默认结算时间已更改至次日 01:30`）。
- **首发合并转发卡片与多次触发引用回复**：
  - 当日首次触发将推送内容包裹在一个合并转发卡片内（包含三段内容，顺序不变，转发人均为“每日推荐”）：
    - 节点 1（标题）：
      ```text
      今日音乐推荐为——
      ```
    - 节点 2（歌曲详情与引导）：
      ```text
      「歌曲名」- 艺术家名
      [封面图片]
      ➫ 你可以对这次日推使用表情回应，让下次的音乐推荐更精准。
      ```
    - 节点 3（音乐卡片）：
      ```text
      [CQ:music,type=163,id={歌曲ID}]
      ```
  - 当日后续再次发送 `/日推`，机器人自动引用回复（`[CQ:reply,id=转发卡片消息ID]`）当天的合并转发卡片：
    ```text
    今日音乐推荐为——
    「歌曲名」- 艺术家名
    ```
- **QQ 表情回应统计与静默结算**：
  - 机器人监听群内表情互动，**表情回应的评价收集仅限该合并转发卡片**（其他消息的回应严格忽略）。评价计算依据为表情数（单用户多表情全部计入）；**点赞类**（包含全部点赞手势、爱心、好评 Emoji 及网络梗表情 “🐛”、“🐋”、“🐍”、“🧊”、“✈️”、“/拜谢”）计入点赞，**踩类**（精选 “/不对不对”、“/续标识”、“❔”、“/棒棒糖”）计入踩；
  - **评价数据群间独立**：即使多个群绑定或共享同一个音乐账号，各群的表情回应与反馈数据互不相通，仅展示与结算本群数据；
  - **静默结算反馈**：
    - **点赞条件**：$赞数 > 踩数 + 3$，自动在网易云音乐调用接口点赞（Like 该单曲）；
    - **减少推荐条件**：$踩数 \ge 赞数$，自动在网易云音乐日推中标记“减少推荐”（Dislike 该单曲）；
    - **其他情况**：保持原样，不做处理；
    - 结算过程完全静默，不向群内发送打扰消息；亦支持群内通过 `/日推 结算`（限管理员）手动提前结算当前群（结算后再次触发提示 `𝐢 | 当日日推评价已结算`）。
- **日推状态面板与重置限制**：
  - `/日推 状态` 面板：未开启提示 `𝐢 | 当前日推功能未开启`；开启后展示今日推荐曲目、实时反馈数据 `[+x]` / `[-x]`（由赞数 - 踩数计算得出）、待结算/已结束评价状态、首次推送时间；
  - 群内发送 `/日推 重置` 或 `/日推 恢复`（限管理员），可清空当天的推送记录、表情投票记录和结算状态；
  - **防跨时重置保护**：若当前时间已过日推默认结算时间，自动拦截并回复 `✕ | 已过日推默认结算时间，不可进行重置`；
  - 重置后即使已过默认推送时间也不会自动补发默认推送，再次手动发送 `/日推` 才会重新发送全新的第一条日推卡片。

### 5. 管理员白名单与私聊扫码登录
- **群聊安全拦截**：群聊中发送 `/登录` 或 `/管理员` 指令将被拦截并提示仅限私聊，防止公开暴露后台状态与二维码。
- **代码硬性管理员白名单**：
  - 内置硬性管理员（`2165242464`），不可通过命令被删除；
  - 尝试删除硬性管理员时自动拦截并提示：`➥ 不可移除管理员 2165242464`。
- **纯本地 Base64 二维码与安全直链**：
  - 调用系统 `/usr/bin/qrencode` 现场生成标准 PNG 图片并转为 Base64 CQ 码发送，无任何第三方图床或外链泄漏风险；
  - 标题规范为 `❐ 网易云音乐扫码登录`；扫码阶段静默等待，用户在手机确认登录后自动推送账号昵称、UID 与 VIP 身份。
- **Cookie 直接导入与清洗**：
  - 支持私聊直接发送 `/登录 <Cookie>`，自动清洗提取有效键值并向网易云服务器在线校验有效性，有效解决官方扫码 8821 风控限制。

### 6. 跨群账号绑定、槽位映射与线性探测机制
- **平台配置抽象**：
  - 平台配置常量（如网易云日推曲目容量 `MAX_RECOMMEND_SLOTS = 35`、日推分界 `RESET_HOUR = 6`）统一在 `NeteasePlatformConfig` 中声明，代码零硬编码。
- **账号 UID 唯一标识与日推槽位映射**：
  - 音乐平台账号通过唯一的 `account_uid` 区分；
  - 同一账号为不同群提供日推服务时，依群绑定时间先后固定分配槽位（Slot $0, 1, 2, \dots$），分别对应日推列表里的第 1 首、第 2 首、第 3 首...；
- **槽位释放与线性探测填补 (Linear Probing)**：
  - 当群执行 `/退出登录 <群号>` 或解除共享时，该群持有的槽位自动释放；
  - 后续新群绑定该账号时，采用线性探测法扫描并优先填补最小可用空槽位（如 slot 2 释放后，新群被分配 slot 2 即第 3 首歌，避免槽位空洞）；
- **绑定群聊数量上限与超限回滚保护**：
  - 单个音乐账号绑定的群聊数量严格限制为平台最大槽位数（35 个）；
  - 达到上限时，后续尝试为新群绑定该账号（Cookie 导入、扫码登录或 `/共享账号`）将被拦截并提示：
    ```text
    ✕ | 共享该账号的群聊数量达到上限。
    ```
  - 触发超限时系统执行自动回滚：若已登录则自动撤销登录，若发起共享则自动取消共享，并彻底清除目标群相关绑定信息。

### 4. 机器人账号登录与网络配置指南（NapCat WebUI）

NapCatQQ 容器化运行作为 OneBot 11 协议端，通过 WebUI 控制台提供直观的账号管理与网络连接配置。

#### 4.1 端口说明与确认

整个系统涉及两个关键端口，它们的用途与确认方式如下：

| 端口号 | 监听方 | 访问/连接方向 | 作用说明 | 确认与查看方式 |
| :--- | :--- | :--- | :--- | :--- |
| **6099** | NapCat WebUI（容器内部） | 浏览器 $\to$ 容器 `6099` | 网页端管理后台，用于扫码登录 QQ、管理网络配置 | 检查 [docker-compose.yml](file:///home/virtualself/Projects/qq-bot/docker-compose.yml) 中的 `ports: - "6099:6099"` 以及 [webui.json](file:///home/virtualself/Projects/qq-bot/napcat/config/webui.json) 中的 `"port": 6099` |
| **3001** | C++ 机器人（宿主机） | NapCat 容器 $\to$ 宿主机 `3001` | WebSocket 服务端，负责接收 QQ 消息事件并发送指令响应 | 源码 [src/main.cpp](file:///home/virtualself/Projects/qq-bot/src/main.cpp#L188) 中 `bot::core::WsServer server(ioc, 3001, "0.0.0.0");`。启动后可通过 `ss -tlnp \| grep 3001` 确认监听 |

> [!NOTE]
> **关于 `host.docker.internal`**：由于 NapCat 运行在 Docker 容器内，无法直接通过 `localhost` 访问宿主机上的服务。我们在 [docker-compose.yml](file:///home/virtualself/Projects/qq-bot/docker-compose.yml#L15-L16) 中配置了 `extra_hosts: "host.docker.internal:host-gateway"`，因此容器内填写的连接地址必须为 `ws://host.docker.internal:3001`。

#### 4.4 新建与检查 OneBot 11 网络配置（WebSocket Client）

登录 QQ 账号后，必须确保 NapCat 将消息推送到宿主机运行的 C++ 机器人：

##### 途径 A：通过 WebUI 可视化新建网络配置
1. 在 NapCat WebUI 左侧导航栏点击 **「网络配置」**。
2. 找到当前已登录的 QQ 账号，点击 **「新建网络配置」** / **「添加配置」**。
3. 选择配置类型：**WebSocket 客户端 (WebSocket Client)**。
4. 填写网络参数：
   - **配置名称**：`bot`（或自定义）
   - **URL / 连接地址**：`ws://host.docker.internal:3001`
   - **消息格式 (Message Post Format)**：选择 `array`（C++ 机器人端基于 Glaze 解析消息链，要求必须为 `array`）
   - **启用连接 (Enable)**：勾选开启
   - **心跳间隔 (Heart Interval)**：`5000` ms
   - **重连间隔 (Reconnect Interval)**：`3000` ms
5. 点击 **保存并应用**。

##### 途径 B：通过本地 JSON 配置文件自动生效
NapCat 在启动时会自动加载挂载目录下的 `napcat/config/onebot11_<QQ号>.json`。对于新账号，可直接基于模板复制：
```bash
cp napcat/config/onebot11_3809397604.json napcat/config/onebot11_<新QQ号>.json
```
标准配置模板 [onebot11_3809397604.json](file:///home/virtualself/Projects/qq-bot/napcat/config/onebot11_3809397604.json) 内容如下：
```json
{
  "network": {
    "httpServers": [],
    "httpSseServers": [],
    "httpClients": [],
    "websocketServers": [],
    "websocketClients": [
      {
        "enable": true,
        "name": "bot",
        "url": "ws://host.docker.internal:3001",
        "reportSelfMessage": false,
        "messagePostFormat": "array",
        "token": "",
        "debug": false,
        "heartInterval": 5000,
        "reconnectInterval": 3000,
        "verifyCertificate": true
      }
    ]
  }
}
```
